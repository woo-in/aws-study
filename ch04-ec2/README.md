# 4장. 서버 서비스 Amazon EC2

> EC2는 **필요할 때 바로 만들고, 필요 없으면 바로 지우는 가상 서버**다.
> 하드웨어는 AWS가 관리하고, OS부터 그 위는 내가 관리한다.

<br/>

## 4.1 Amazon EC2란 — 짧은 시간에 실행 환경을 구축할 수 있는 가상 서버

**Amazon Elastic Compute Cloud** — 컴퓨팅 용량(가상 서버)을 빌려주는 서비스.

### 매니지드 서비스가 아니다

| 누가 관리하나 | 범위 |
| --- | --- |
| **AWS** | 물리 서버, 네트워크, 데이터센터 등 **하드웨어·인프라** |
| **사용자** | **OS**와 그 위의 소프트웨어 설치·설정·운영 (패치, 보안 포함) |

### 특징

- **클릭 한 번으로 서버 생성** — 두 가지만 고르면 된다.
  - **인스턴스 유형**: 하드웨어 사양 조합 (CPU, 메모리 등)
  - **AMI**: OS + 소프트웨어 조합
- **바로 만들고 바로 지운다**
  - 불필요한 리소스를 유지할 필요가 없다.
  - 서버에 문제가 생겨도 즉시 새로 만들어 복구할 수 있다.
  - 복제, 스케일 아웃/인, 스케일 업/다운이 쉽다.
  - 이벤트 사이트처럼 **일시적으로 접속이 몰리는 경우**, **불확실성이 큰 경우**에 특히 유용하다.

<br/>

## 4.2 EC2의 사용 절차 — 가상 서버를 사용하기까지

### 서버 관리자의 두 가지 업무

| 업무 | 방법 |
| --- | --- |
| 1. 서버 하드웨어·주변 환경 구축 | **EC2 관리 콘솔** |
| 2. 서버 OS에 로그인해서 작업 | **SSH**로 원격 접속 (온프레미스와 동일) |

### EC2 구성 요소

| 구성 요소 | 설명 |
| --- | --- |
| **인스턴스** | AWS 클라우드에 만든 가상 서버. AMI로 같은 구성의 서버를 몇 번이고 생성 가능 |
| **AMI** | 가상 머신 이미지. OS만 있는 것부터 소프트웨어까지 설정된 것까지 다양 |
| **키 페어** | 인스턴스 접속 시 인증에 쓰는 키 |
| **EBS** | 인스턴스의 스토리지(디스크) |
| **보안 그룹** | 가상 방화벽. 1개 이상의 인스턴스 트래픽을 제한 |
| **Elastic IP** | 고정 공인 IPv4 주소 |

### 사용 순서

```
1. 인스턴스 생성
   AMI 선택 → 인스턴스 유형 선택 → 네트워크/IP 할당 → 스토리지 추가 → 보안 그룹 설정 → 키 페어 선택
2. SSH로 인스턴스에 접속
3. 소프트웨어 설치·설정
```

### 인스턴스 설정 항목

| 항목 | 설명 |
| --- | --- |
| AMI | OS + 소프트웨어 이미지 |
| 인스턴스 유형 | 장비 사양 (CPU, 메모리, 장비 유형) |
| 리전 | 서버를 둘 지역 |
| 네트워크 | 인스턴스를 배치할 **VPC** |
| 서브넷 | VPC 안의 네트워크 범위. 고르면 **AZ(설치 장소)** 와 **사설 IP 대역**이 정해짐 |
| 스토리지 | 보통 **EBS**. 용량과 종류(주로 `gp3`)를 선택 |
| 태그 | 인스턴스에 붙이는 임의의 이름표 (관리·비용 구분용) |
| 보안 그룹 | 프로토콜·포트·IP 주소별 허용 규칙 |

### 리전 · AZ · VPC · 서브넷

| 구분 | 무엇 | 성격 |
| --- | --- | --- |
| **리전** | 서버가 위치한 지역 (예: 서울) | 물리적 — AWS가 정해둔 실제 장소 |
| **AZ** | 리전 안의 데이터센터 묶음 | 물리적 |
| **VPC** | 나만의 사설 네트워크 | 논리적 — 내가 설계 |
| **서브넷** | VPC를 쪼갠 구역 | 논리적 |

```
서울 리전
└─ VPC (10.0.0.0/16)
   ├─ AZ 2a
   │   ├─ 퍼블릭 서브넷  (10.0.1.0/24) → EC2, NGINX
   │   └─ 프라이빗 서브넷 (10.0.2.0/24) → DB
   └─ AZ 2c
       ├─ 퍼블릭 서브넷  (10.0.3.0/24)
       └─ 프라이빗 서브넷 (10.0.4.0/24)
```

- VPC는 리전 단위, **서브넷은 AZ 하나에 묶인다.**
- 서브넷을 여러 AZ에 나눠 두면 한 데이터센터가 멈춰도 다른 AZ에서 서비스를 계속할 수 있다 → **고가용성(Multi-AZ)** 구성.

### 사설 IP · 공인 IP · NAT

| | 사설 IP | 공인 IP |
| --- | --- | --- |
| 범위 | VPC 같은 내부 네트워크 안에서만 | 인터넷 전체에서 유일 |
| 중복 | 다른 네트워크끼리는 같은 주소 사용 가능 | 불가 |
| 인터넷에서 직접 접근 | 불가 | 가능 |

- **NAT (Network Address Translation)**: 사설 IP ↔ 공인 IP 주소를 바꿔주는 기술
- **EC2에서는**
  - 인스턴스(OS)에는 **사설 IP만** 붙어 있다.
  - 공인 IP는 인스턴스 밖에서 AWS가 매핑하고, 이 변환은 **인터넷 게이트웨이**가 한다.
- **기본 VPC**
  - 리전마다 하나씩 자동으로 생성되어 있다.
  - 인터넷 게이트웨이가 이미 붙어 있고, 인스턴스를 만들면 공인 IP가 자동으로 붙는다.
  - VPC를 직접 만들면 이 설정을 전부 직접 해야 한다. (→ 6장)

## 4.3 인스턴스 생성과 요금 — 가상 서버 생성 예시

책의 실습 파트 (콘솔에서 인스턴스 생성 예시).

- 요금은 기본적으로 **인스턴스가 실행 중인 시간**만큼 과금된다. (정지하면 인스턴스 요금은 멈추지만, **EBS 볼륨 요금은 계속** 나간다.)
- 대표적인 구매 옵션: **온디맨드**(쓴 만큼), **예약 인스턴스 / Savings Plans**(장기 약정 할인), **스팟 인스턴스**(남는 용량을 싸게, 대신 회수될 수 있음)

## 4.4 AMI — OS 및 소프트웨어가 설치된 디스크 이미지

**Amazon Machine Image** — OS와 소프트웨어가 설치된 디스크 이미지.

- AWS가 제공하는 AMI 외에 **개인도 AMI를 만들 수 있다.** (내 인스턴스 → AMI → 같은 서버 복제)
- **AWS Marketplace**: 벤더·개인이 AMI를 배포(판매)하는 곳

<br/>

## 4.5 인스턴스 유형 — 용도에 맞게 머신을 선택하자

인스턴스 유형 = 용도에 맞게 CPU·메모리·스토리지·네트워크를 조합한 머신 사양.

### 이름 읽는 법

```
t2.micro
│ │  └─ 크기 (nano, micro, small, medium, large, xlarge, ...)  → CPU·메모리 양
│ └──── 세대 (숫자가 클수록 최신)
└────── 패밀리 (대략적인 용도)
```

### 패밀리별 용도

| 분류 | 패밀리 (책 기준) | 용도 |
| --- | --- | --- |
| 범용 | T2, T3, M4, M5 | 웹 서버 등 균형 잡힌 워크로드. T는 버스트형 |
| 컴퓨팅 최적화 | C4, C5 | CPU를 많이 쓰는 작업 (배치, 인코딩) |
| 메모리 최적화 | X1e, X1, R4 | 인메모리 DB, 캐시 |
| 가속화된 컴퓨팅 | P2, P3, G3, F1 | GPU·FPGA (머신러닝, 그래픽) |
| 스토리지 최적화 | H1, I3, D2 | 대용량·고속 디스크 I/O |

> 📝 책은 2021년 기준이라 세대가 오래됐다. 지금은 M7·C7·R7 같은 최신 세대와 Graviton(ARM, 이름에 `g`) 인스턴스가 있다.

<br/>

## 4.6 Amazon EBS — EC2의 스토리지 볼륨

**Elastic Block Store** — EC2에 붙여 쓰는 **영구 블록 스토리지** (= 인스턴스의 디스크).

- OS, 애플리케이션, Docker 이미지, DB 데이터 등이 저장되는 곳
- **스냅샷**으로 백업하며, 스냅샷은 S3에 저장된다.
- 주로 쓰는 볼륨 유형: **`gp3`** (범용 SSD)

### 블록 스토리지(EBS) vs 오브젝트 스토리지(S3)

| | EBS (블록) | S3 (오브젝트) |
| --- | --- | --- |
| 저장 단위 | 블록 | 오브젝트 (파일 통째) |
| 접근 방식 | OS가 디스크로 마운트 | HTTP API |
| 부분 수정 | 가능 | 불가 (전체 교체) |
| 속도 | 빠름 (지연 시간 낮음) | 상대적으로 느림 |
| 연결 | 한 인스턴스에 붙음 | 어디서든 접근 가능 |
| 범위 | **AZ** | **리전** (여러 AZ에 자동 복제) |
| 용량 | 미리 크기를 정함 | 무제한, 쓴 만큼 과금 |

### 디스크 성능: IOPS vs 처리량

| | IOPS | 처리량 (Throughput) |
| --- | --- | --- |
| 의미 | 1초에 몇 **번** 읽기/쓰기 하나 | 1초에 몇 **MB** 처리하나 |
| 단위 | 횟수/초 | MB/s |
| 중요한 작업 | 작은 데이터를 랜덤하게 자주 읽고 씀 | 큰 파일을 순서대로 읽고 씀 |
| 예시 | DB 쿼리, 트랜잭션 | 로그 분석, 대용량 복사, 백업 |

```
처리량 = IOPS × 한 번에 처리하는 데이터 크기
예) 16KB × 3,000 IOPS ≈ 48MB/s
```

## 4.7 SSH를 사용한 접속과 키 페어 — 공개 키 암호 방식을 이용한 접근 관리

### SSH

- 서버에 원격 접속하기 위한 프로토콜
- **서버**: SSH 데몬(`sshd`)이 실행 중
- **클라이언트**: 터미널의 `ssh`, PuTTY, Tera Term 등

```bash
ssh -i my-key.pem ec2-user@<공인 IP>
```

### 키 페어 = 공개 키 + 개인 키

| 키 | 위치 |
| --- | --- |
| **공개 키** | 인스턴스 쪽 (`~/.ssh/authorized_keys`) |
| **개인 키** | 내 PC (생성 시 **한 번만** 내려받는 `.pem` 파일) |

- 개인 키를 잃어버리면 AWS도 다시 줄 수 없다 → 기본적으로 **서버를 재구축**해야 한다.
- 키 페어는 **리전 단위** 리소스다. 같은 리전 안에서는 여러 인스턴스가 같은 키 페어를 공유할 수 있다.

<br/>

## 4.8 Elastic IP 주소 — 고정 공인 IP 주소를 부여

**EIP** — AWS가 제공하는 **고정(정적) 공인 IPv4 주소**.

- EC2 인스턴스는 **정지 후 다시 시작하면 공인 IP가 바뀐다.**
- 주소가 바뀌면 안 되는 서버에는 EIP를 확보해서 인스턴스에 연결한다.
- EIP는 **AWS 계정 단위**로 확보한다.

> 💸 확보만 하고 쓰지 않는 EIP에도 요금이 붙는다. (2024년부터는 사용 중인 공인 IPv4 주소도 과금)

<br/>

## 4.9 Elastic Load Balancing — 트래픽을 분배하는 분산 장치

**ELB** — AWS가 제공하는 로드 밸런서. 들어오는 트래픽을 여러 인스턴스에 분산한다.

| 종류 | 계층 | 프로토콜 | 특징 |
| --- | --- | --- | --- |
| **ALB** (Application) | L7 애플리케이션 | HTTP, HTTPS | URL 경로·호스트 기반 라우팅 |
| **NLB** (Network) | L4 전송 | TCP, UDP, TLS | 초고성능, 고정 IP |
| **CLB** (Classic) | L4/L7 | — | 구세대, 현재는 비권장 |

> 📝 현재는 여기에 **GWLB**(Gateway Load Balancer, 방화벽 같은 보안 장비용)도 있다.

<br/>

## 4.10 스냅샷 — 서버 데이터 백업

**스냅샷** — 특정 시점의 EBS 볼륨(디스크) 상태를 통째로 보존한 백업. S3에 저장된다.

### 쓰는 이유

- 문제가 생기면 그 시점으로 **바로 되돌릴 수 있다.**
- 개인이 **AMI를 만들 때** 사용된다.

### 스냅샷으로 할 수 있는 것

```
EBS 볼륨 ──스냅샷 생성──▶ 스냅샷 (S3)
                           │
                           ├─▶ 새 EBS 볼륨 생성 (원래 볼륨의 복제본, 다른 AZ에도 가능)
                           └─▶ AMI 생성
```

<br/>

## 4.11 오토 스케일링 — 수요에 맞춰 EC2 대수를 증감

**Auto Scaling** — 서버의 부하(접속 상태)에 따라 EC2 **대수를 자동으로 늘리거나 줄이는** 기능.

- 접속이 늘면 인스턴스 추가(스케일 아웃), 줄면 제거(스케일 인)
- 보통 **ELB와 함께** 쓴다. 새로 생긴 인스턴스를 로드 밸런서가 자동으로 트래픽 분산 대상에 넣는다.

<br/>

## 핵심 요약

- EC2 = **인스턴스 유형(하드웨어) + AMI(OS·소프트웨어)** 를 골라 바로 만드는 가상 서버. OS부터는 내가 관리한다.
- 리전·AZ는 **물리적 장소**, VPC·서브넷은 그 위에 내가 만드는 **논리적 네트워크**. 서브넷은 AZ 하나에 속한다.
- 인스턴스엔 사설 IP만 있고, 공인 IP 변환은 **인터넷 게이트웨이**가 한다. 고정 공인 IP가 필요하면 **EIP**.
- 디스크는 **EBS**(블록, AZ 단위), 백업은 **스냅샷**(S3에 저장, AMI 생성에도 사용).
- 접속은 **SSH + 키 페어** — 공개 키는 서버에, 개인 키는 내 PC에.
- 트래픽 분산은 **ELB**(ALB=L7, NLB=L4), 대수 조절은 **오토 스케일링**.
