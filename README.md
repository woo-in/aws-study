## 📌 이 책을 읽는 이유

AWS를 간단하게 사용해 본 적은 있지만, **잘 모르고 썼습니다.**
콘솔을 열 때마다 VPC, 서브넷, 보안 그룹, IAM, AMI처럼 **모르는 용어들이 계속 나왔고**, 설정값의 의미를 모른 채 넘어가는 일이 반복됐습니다.

- 따라 하면 동작은 했지만, 각 설정이 무엇을 뜻하고 왜 필요한지 설명할 수 없었습니다.
- 용어를 모르니 문서를 읽어도 막히고, 같은 부분에서 매번 다시 헤맸습니다.

그래서 **한 번은 개념을 제대로 익혀 두자**는 생각으로, 그림으로 AWS의 구조를 풀어 주는 이 책을 읽습니다.

### 2장. AWS를 이해하기 위한 클라우드 & 네트워크의 구조

🔗 [#1 docs: 2장 AWS를 이해하기 위한 클라우드 & 네트워크의 구조 정리 (ch02)](https://github.com/woo-in/aws-study/pull/1) · 📝 [정리 노트](./ch02-cloud-and-network/README.md)

- 클라우드는 **가상화**(물리 서버 한 대 → 가상 서버 여러 대)와 **분산 처리**(여러 대에 나눠 맡기기) 위에 서 있다. 요청을 나눠 주는 로드 밸런서가 AWS의 **ELB**다.
- **SaaS · PaaS · IaaS**는 사업자가 어디까지 준비해 주느냐의 차이다. EC2는 인프라만 빌리는 **IaaS**라서 OS부터 직접 관리한다.
- IP 주소는 **네트워크부 + 호스트부**로 나뉘고, 경계는 서브넷 마스크(`/24`)가 정한다. VPC `10.0.0.0/16`을 서브넷 `10.0.1.0/24`로 쪼개는 게 바로 이 개념이다.
- **SSH**는 전 구간을 암호화하는 원격 접속 프로토콜이다. 개인 키(`.pem`)는 내 PC, 공개 키는 서버에 두는 키 인증이 EC2 **키 페어**다.

### 3장. AWS를 사용하기 위한 도구

🔗 [#2 docs: 3장 AWS를 사용하기 위한 도구 정리 (ch03)](https://github.com/woo-in/aws-study/pull/2) · 📝 [정리 노트](./ch03-aws-tools/README.md)

- **루트 사용자**는 계정의 모든 권한을 가진다. 평소에는 필요한 권한만 준 **IAM 사용자**로 작업한다.
- **IAM 정책**은 무엇에 대하여(`Resource`) 어떤 조작을(`Action`) 허가할지 말지(`Effect`)를 정한다. 정책은 **그룹**에 붙이고, 사용자는 그룹에 넣어 관리한다.
- **CloudWatch**는 CPU 사용률 같은 지표와 로그를 모으고, 임계값을 넘으면 이메일 · EC2 시작/정지 · Auto Scaling · Lambda 실행으로 대응한다.
- **리전 ⊃ 가용 영역(AZ) ⊃ 데이터 센터**. 서버를 여러 AZ에 나눠 두면 AZ 하나가 멈춰도 서비스가 계속된다. 콘솔 조작도 리전 단위다.
